\chapter{HTTP and framework quick reference}

\section{Request and response shapes}

\begin{wiremessage}
METHOD /path?query=value HTTP/1.1
Host: authority
Field-Name: field value
Content-Length: number-of-body-bytes

optional body bytes
\end{wiremessage}

\begin{wiremessage}
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Content-Length: number-of-body-bytes
Connection: keep-alive

optional body bytes
\end{wiremessage}

Every displayed line ending above is CRLF. Exactly one empty line terminates the
field section. Content-Length counts octets in the framed body.

\section{Framework public API}

\begin{itemize}
  \item \code{Headers(values)}, \code{add}, \code{set}, \code{remove},
        \code{get}, \code{get\_all}, \code{copy}, \code{items};
  \item Request message fields: \code{method}, \code{target}, \code{version},
        \code{headers}, and \code{body};
  \item Request routing helpers: \code{path}, \code{query}, \code{client},
        \code{path\_params}, and \code{json()};
  \item \code{Response(status, body, headers)}, \code{Response.json},
        and \code{Response.problem};
  \item \code{Application.route}, \code{add\_middleware}, and \code{handle};
  \item \code{ServerConfig} and \code{Server.serve\_forever},
        \code{wait\_until\_ready}, \code{shutdown};
  \item \code{HTTPError(status, detail, code, title, errors, type\_uri)}.
\end{itemize}

\section{Parser decision sequence}

\begin{enumerate}
  \item Is a complete CRLF--CRLF header section buffered?
  \item Are line and total header sizes within limits?
  \item Are all line endings strict and request-line components valid?
  \item Is the version exactly HTTP/1.1?
  \item Are field names/values legal and exactly one Host present?
  \item Is framing unambiguous and supported?
  \item Is declared body size within limit and fully buffered?
  \item Can origin-form target, percent encoding, path, and query be decoded?
  \item Consume exactly one message and preserve the remainder.
\end{enumerate}

\section{Code review checklist}

\begin{itemize}
  \item Every network wait has a bound or documented owner.
  \item Every allocated resource closes on success and failure.
  \item Every input collection has size/count limits.
  \item HTTP and JSON byte/text conversions name their encoding.
  \item Framing ambiguity closes the connection.
  \item Handlers return Response rather than touching sockets.
  \item SQL structure is code-owned and values are bound parameters.
  \item 500 responses reveal no internal exception detail.
  \item Tests include fragments, combined messages, boundaries, and cleanup.
  \item Documentation states unsupported features explicitly.
\end{itemize}
